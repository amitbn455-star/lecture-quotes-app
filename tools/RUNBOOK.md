## צעדים
1. **האירוע.** `get_event` לפי ה-eventId. אם נמחק/בוטל, או שכבר לא מתאים לתבנית, או שהשעה שלו
   מסתיימת יותר מ-5 דקות בעתיד (הוזז) — סיים בלי לעשות כלום (המתכנן היומי יסדר מחדש).
   `client` = הטקסט אחרי `הרצאה — `. תאריך האירוע = תאריך ההתחלה בשעון ישראל, בפורמט DD.MM.YYYY.
2. **הנתונים.** קרא את A1. אם אינו JSON תקין או שאין בו הצעות: שלח הודעה דחופה לעמית
   ("לא הופק חשבון: הגיליון לא נטען") וסיים, בלי לכתוב כלום. שמור את התוכן הגולמי בדיוק כפי שהוא ב-`/tmp/data.json`.
3. **התאמת הצעה (לפי שם הלקוח, לא לפי מספר ההצעה שבתיאור האירוע, כי הוא עלול להיות ישן).**
   מועמדות = הצעות ש-`client` זהה בדיוק לשם, `status` אינו `rejected`, ו-`invoiced` אינו true.
   - אם יש מועמדת אחת בלבד, או רק אחת ש-`ldate` שלה שווה לתאריך האירוע: זו ההצעה.
   - אם כבר קיימת הצעה של אותו לקוח עם `ldate` זהה ו-`invoiced` true: חשבון כבר הוצא. סיים בשקט.
   - אין מועמדת, או כמה מועמדות שאי אפשר להכריע ביניהן: שלח הודעה לעמית ("לא הופק חשבון ל-X: <סיבה>") וסיים.
4. **הפקה.**
   ```
   git clone --depth 1 https://github.com/amitbn455-star/lecture-quotes-app /tmp/app
   npm install --silent --no-audit --no-fund --prefix /tmp/fonts @fontsource/assistant
   cd /tmp/app && node tools/make_invoice.js /tmp/data.json <quoteId> "/tmp/חשבון עסקה - <client>.pdf" /tmp/inv.json
   ```
   (שם הקובץ: שמות לקוח עם תווים אסורים — `/ \ : * ? " < > |` — מוחלפים ברווח.)
   ודא שהקובץ נוצר ושב-`inv.json` יש `invNum`.
5. **שליחה לעמית.** `SendUserFile` עם `status: "proactive"`, `display: "attach"` וכיתוב קצר בעברית:
   "חשבון עסקה <invNum> ל-<client> על <invGrand> ₪ (ההרצאה הייתה ב-<תאריך>)". אל תתאר את תוכן המסמך.
6. **סימון בגיליון (רק אחרי ששלחת).**
   - קרא שוב את A1 (טרי) ושמור ל-`/tmp/fresh.json`.
   - `python3 /tmp/app/tools/merge_quote.py /tmp/fresh.json /tmp/inv.json /tmp/merged.json`
     (קוד 3 = כבר סומן, סיים בשקט; קוד 4/5 = שלח לעמית הודעה עם הפרטים ואל תכתוב).
   - כתוב את תוכן `/tmp/merged.json` ל-A1 כמו שהוא (`RAW`, בלי עיצוב).
   - קרא חזרה את A1 ובדוק: JSON תקין, אותו מספר הצעות ולקוחות כמו ב-`fresh.json`, ו-`invoiced` true להצעה.
     אם נכשל: כתוב שוב את `/tmp/fresh.json` המקורי כדי לשחזר, ושלח לעמית הודעה שהחשבון נשלח אך לא סומן בגיליון (עם מספר החשבון).
7. סיים בשורה אחת: מה הופק ולמי.

## תזמון הרצאה חדשה (מופעל מכפתור "⏰ תזמן חשבון" באפליקציה)

מטרה: שהחשבון יצא ממש בסיום ההרצאה, גם כשההרצאה נוספה ביומן באותו יום (המתכנן היומי מכסה רק הרצאות שנוספו מראש).
הקלט: לקוח, מספר הצעה, תאריך (DD.MM.YYYY) ושעות (ברירת מחדל 19:00–20:00, שעון ישראל).

1. `list_events` ביומן "הרצאות" לאותו תאריך. אם יש אירוע עם שעה והכותרת `הרצאה — <לקוח>`: זה האירוע (קח את ה-id והשעות שלו).
   אחרת `create_event` ביומן "הרצאות" (Asia/Jerusalem): כותרת `הרצאה — <לקוח>`, תיאור `הצעה מס׳ <מספר>`, ושעות מההנחיה.
2. `list_triggers` (include_completed=true): אם כבר קיימת משימה ששמה מכיל את ה-eventId, אל תיצור שנייה. דווח שכבר מתוזמן.
3. אחרת `create_trigger`: name=`חשבון עסקה | <eventId> | <לקוח> | <תאריך>`, initiation=`human_request`,
   run_once_at = שעת סיום האירוע + 10 דקות (UTC, RFC3339; חייב להיות בעתיד), notifications={"push":true},
   prompt:
   > הוצאת חשבון עסקה אוטומטית אחרי הרצאה, מצב רגיל (לא TEST). eventId: <EID>. יומן הרצאות: 6f1e52d16abc56f988c855fb0a76ddd25f747950ca318c7336765e58ab126e2c@group.calendar.google.com. שכפל git clone --depth 1 https://github.com/amitbn455-star/lecture-quotes-app /tmp/app, קרא את tools/RUNBOOK.md ובצע אותו במלואו לאירוע הזה. שלח רק לעמית ולעולם לא ללקוחות.
4. ענה בשורה אחת: האירוע (נוצר/קיים) ומתי יצא החשבון. אם שעת היעד כבר עברה, אמור זאת ושאל אם להפיק עכשיו.
